# 테스트 시나리오 (TEST_SCENARIOS.md)

## TC-01: 학생 리스트 로딩
| 항목 | 내용 |
|------|------|
| **목적** | 앱 접속 시 학생 목록이 정상 표시되는지 확인 |
| **사전조건** | 원본 시트에 "3월" 탭과 학생 데이터 존재 |
| **절차** | 1. 앱 URL 접속 → 2. 구글 계정 로그인 → 3. 학생 목록 확인 |
| **기대결과** | 호실, 학번, 이름이 표시된 학생 카드 리스트 노출 |

## TC-02: 학생 검색/필터
| 항목 | 내용 |
|------|------|
| **목적** | 검색 및 필터 기능 정상 동작 확인 |
| **절차** | 1. 검색창에 학번/이름/호실 입력 → 2. "벌점 있음" 필터 클릭 |
| **기대결과** | 검색어에 맞는 학생만 표시 / 벌점 있는 학생만 표시 |

## TC-03: 외출 토글 ON/OFF
| 항목 | 내용 |
|------|------|
| **목적** | 외출 버튼 토글이 정확히 동작하는지 확인 |
| **절차** | 1. 학생 상세 → 2. 외출 버튼 클릭 (ON) → 3. 외출 횟수 +1 확인 → 4. 다시 클릭 (OFF) → 5. 횟수 -1 확인 |
| **기대결과** | 횟수 증감 정확, APP_외출외박로그에 active/removed 기록, 원본 시트 E열 자동 갱신 |
| **원본확인** | 원본 시트 E열(외출 횟수) 값이 앱과 동일한지 확인 |

## TC-04: 외박 초과 벌점 자동 부과
| 항목 | 내용 |
|------|------|
| **목적** | 외박 3회째에 자동 벌점(5점)이 부과되는지 확인 |
| **절차** | 1. 외박 3회 기록 → 2. 총 벌점 확인 |
| **기대결과** | 초과 1회 × 5점 = 5점 자동 부과, 총 벌점에 반영, 원본 M열 동기화 |
| **원본확인** | 원본 시트 J열(외박 벌점)=5, M열(총벌점)에 반영 |

## TC-05: 벌점 항목 선택 부여
| 항목 | 내용 |
|------|------|
| **목적** | 벌점 항목 선택 후 학생에게 정확히 부여되는지 |
| **절차** | 1. 학생 상세 > "벌점 부여" → 2. "청소 불이행(3점)" 선택 → 3. 메모 입력 → 4. 부여 |
| **기대결과** | 총 벌점 +3, APP_벌점로그에 기록, APP_누가기록에도 자동 기록, 원본 M열 동기화 |

## TC-06: 문자 템플릿 (귀사시간 반영)
| 항목 | 내용 |
|------|------|
| **목적** | SMS 딥링크에 템플릿 본문과 귀사시간이 반영되는지 |
| **절차** | 1. 외출 기록 → 2. 귀사시간 "18:00" 입력 → 3. 학부모 "문자" 버튼 클릭 |
| **기대결과** | 폰 문자 앱이 열리며 "귀사 예정 시간: 18:00" 포함된 본문 노출, 바로 발송 안 됨 |

## TC-07: 사감 근무 조회
| 항목 | 내용 |
|------|------|
| **목적** | 교사 이름 선택 시 근무일이 필터링되는지 |

## TC-08: 감사 로그 확인
| 항목 | 내용 |
|------|------|
| **목적** | 모든 변경 작업이 감사 로그에 기록되는지 |
| **절차** | 1. 외출 토글 → 2. 벌점 부여 → 3. APP_DB > APP_감사로그 탭 확인 |

## TC-09: 교사 건의사항 CRUD
| 항목 | 내용 |
|------|------|
| **목적** | 건의사항 작성, 조회, 상태 변경이 정상 동작하는지 |

## TC-10: 원본 시트 동기화 확인
| 항목 | 내용 |
|------|------|
| **목적** | 앱에서의 모든 변경이 원본 시트에도 정확히 반영되는지 |
| **절차** | 1. 외출 2회 + 외박 3회 기록 → 2. 벌점 "기물파손(5점)" 부여 → 3. 원본 시트 확인 |
| **기대결과** | 원본 E=2, I=3, F=0, J=5(외박초과1회), M=10(5+5), N=봉사활동 |
| **확인사항** | 원본 시트의 기존 수식/포맷이 깨지지 않았는지 (해당 셀만 값 업데이트) |
